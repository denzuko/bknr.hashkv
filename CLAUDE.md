## Standards Stack

- Roswell and qlot. `qlfile` pins bknr.ttl, sunny-side and
  denzuko/bknr-datastore by git; `qlfile.lock` records the commits.
- ASDF systems: `bknr.hashkv` (library), `/tests`, `/e2e`, `/bdd`,
  `/docs`, `/ci`. Library code lives in `src/`; `bknr.hashkv.ros` only
  dispatches subcommands.
- CI is generated by 40ants-ci from `src/ci.lisp`. Edit that file, then
  regenerate `.github/workflows/ci.yml` with
  `(40ants-ci:generate :bknr.hashkv/ci)`.
- git-flow; `develop` is the integration branch.
- Semver: MAJOR for a rewrite or a change that breaks downstream
  callers; MINOR for new capability; PATCH for everything else.

## BDD Workflow

Gherkin feature (`features/*.feature`, run by sunny-side) → gate →
FiveAM unit and e2e tests → code → changelog → merge → tag.
`bdd-rigor-check` must report the boundary, invalid input, concurrency
and persistence categories as addressed for each feature file.

## Quality Gates

- `.github/scripts/gate.ros`: G1 reads every source file with the Lisp
  reader; G2 rejects bare `(if ...)` and `(is (not ...))`; G3 rejects
  listed voice violations in docstrings.
- `.github/scripts/cover.ros`: runs every suite on an sb-cover build and
  fails below 100% branch coverage of `src/`. sb-cover measures
  branches, not MC/DC.

## Subcommands

- `./bknr.hashkv.ros bdd | test | e2e | docs`

## Do Not

- Do not keep state in special variables. Store state belongs to the
  store object (`hashkv-store`); test and step state is lexical.
- Do not read an entry outside the transaction that writes it. Use
  `store-entry` or `with-found-entry`.
- Do not remove a slot from `kv-entry` or `queue-entry`. bknr.datastore
  refuses to restore a snapshot that names a slot the class lacks.
- Do not edit Lisp source with Python or other text substitution; use
  structural edits and run the gate.
- Do not add a network protocol, publish/subscribe, eviction or
  replication.
